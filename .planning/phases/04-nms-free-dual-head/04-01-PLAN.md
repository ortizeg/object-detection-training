**1. Create `hungarian.py`** with `HungarianAssigner` class:
- Same constructor pattern as `TaskAlignedAssigner`: takes `alpha`, `beta`, `num_classes`.
- `assign()` method with IDENTICAL signature and 5-tuple return contract as TAL's `assign()` (see `tal.py` lines 178-191 for exact signature).
- Steps inside `assign()`:
  1. Early return zero-fg 5-tuple if `num_gt == 0` (same pattern as TAL).
  2. Spatial filtering via duplicated `_get_in_boxes_info` (copy from `tal.py`, same as SimOTA/TAL pattern -- avoid circular import by duplicating).
  3. Filter to candidate anchors. If `num_candidates == 0`, return zero-fg 5-tuple.
  4. Compute pairwise IoU `[num_gt, num_candidates]` using duplicated `_bboxes_iou` (same pattern as `tal.py`).
  5. Compute cls score: `cls_sigmoid = cls_preds_cand.sigmoid()`, then `bbox_scores[g, a] = cls_sigmoid[a, gt_class[g]]` using one-hot dot product (same as TAL lines 250-259).
  6. Alignment metric: `alignment = bbox_scores.pow(alpha) * pair_wise_ious.pow(beta)`.
  7. Cost matrix: `cost = -alignment + 1e6 * (~is_in_boxes_and_center)`.
  8. Solve: `row_ind, col_ind = linear_sum_assignment(cost.detach().cpu().numpy())`.
  9. Convert to 5-tuple: build `fg_mask` bool tensor of size `total_num_anchors`, set True at matched candidate positions. `num_fg = len(row_ind)` (equals `num_gt`). Extract `gt_matched_classes`, `pred_ious_this_matching`, `matched_gt_inds` from the matching.
- Decorate `assign()` with `@torch.no_grad()`.
- Import `from scipy.optimize import linear_sum_assignment`.
- Duplicate `_bboxes_iou` and `_get_in_boxes_info` from `tal.py` (same pattern -- avoid circular import).

**2. Update `config.py`**:
- Add `lambda_o2o: float = 1.0` field in the "Future phases: dual head" section.
- No new validators needed -- existing `use_dual_head requires use_soft_labels` validator already exists.

**3. Update `dinox_head.py`**:
- Add `use_dual_head: bool = False` and `lambda_o2o: float = 1.0` constructor params.
- Store as `self.use_dual_head` and `self.lambda_o2o`.
- Add import: `from .hungarian import HungarianAssigner`.
- **O2O prediction layers** (in `__init__`, gated on `use_dual_head`):
  - Create `self.cls_preds_o2o`, `self.reg_preds_o2o` as `nn.ModuleList` with same structure as O2M preds (same Conv2d specs per FPN level). NO `obj_preds_o2o` -- skip per research recommendation.
  - After creating O2O layers, copy O2M weights: `self.cls_preds_o2o[i].load_state_dict(self.cls_preds[i].state_dict())` and same for reg_preds.
  - Instantiate `self._hungarian_assigner = HungarianAssigner(alpha=tal_alpha, beta=tal_beta, num_classes=num_classes)`.
- **O2O inference path** (in `_forward_inference`):
  - When `self.use_dual_head`, use `self.cls_preds_o2o[k]` and `self.reg_preds_o2o[k]` instead of O2M layers.
  - Output constant-1 objectness: `obj_output = torch.ones(B, 1, H, W, device=..., dtype=...)`.
  - Concatenate: `output = torch.cat([reg_output, obj_output, cls_output.sigmoid()], 1)`.
- **O2O training path** (in `_forward_train`):
  - After computing O2M outputs per FPN level, additionally compute O2O predictions using `self.cls_preds_o2o[k]` and `self.reg_preds_o2o[k]` on the SAME `cls_feat` and `reg_feat` (shared conv stacks).
  - Store O2O outputs in parallel lists, concatenate, and pass to `_get_losses`.
- **Combined loss** (in `_get_losses`):
  - Accept O2O outputs as additional parameter (e.g., `o2o_outputs: torch.Tensor | None = None`).
  - After O2M loss computation per batch image, if `self.use_dual_head` and `o2o_outputs is not None`:
    - Extract O2O bbox/cls preds from `o2o_outputs`.
    - Run `self._hungarian_assigner.assign(...)` with O2O predictions.
    - Compute O2O cls_loss and iou_loss using same loss functions.
    - O2O has NO objectness loss (O2O skips obj_preds entirely).
    - Track O2O losses and num_fg_o2o separately.
  - After batch loop, normalize O2O losses by O2O's own num_fg.
  - Combine: `loss = L_o2m + self.lambda_o2o * (reg_weight * iou_loss_o2o + cls_loss_o2o)`.
  - Return total loss (combined) in position 0 of the 6-tuple. Individual loss components reported remain O2M values (for logging continuity).
