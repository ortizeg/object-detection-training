**dinox_lightning.py** - Create DINOXLightningModel extending BaseDetectionModel. Follow yolox_lightning.py pattern closely but with DINO-X specific changes:

Constructor params (matching Hydra config flow pattern): num_classes, pretrain_weights, learning_rate, weight_decay, warmup_epochs, download_pretrained, input_height, input_width, image_mean, image_std, output_dir, freeze_backbone_epochs, l1_loss_epoch, iou_loss_type, depth, width, depthwise, in_channels, checkpoint_name (default "yolox_m.pth"), PLUS new DFL params: use_dfl (bool, False), reg_max (int, 16), dfl_loss_weight (float, 0.25)

Build model:
1. Create YOLOPAFPN backbone (same as YOLOX)
2. Create DINOXHead with use_dfl, reg_max, num_classes, width, in_channels, depthwise
3. Create DINOX(backbone, head) and store as self.model
4. Construct DINOXConfig internally from kwargs for validation (fail fast if invalid flag combo)
5. Override IoU loss type if not "iou" (same pattern as YOLOX)
6. Initialize BN eps/momentum (same as YOLOX)
7. Call head.initialize_biases(prior_prob=1e-2)
8. Load pretrained weights via _load_weights or _download_and_load_weights
9. Reinitialize cls_preds biases after weight loading
10. Freeze backbone if requested

**_load_weights** - Copy the YOLOX pattern: load checkpoint, match state dict keys, skip shape mismatches (this handles DFL reg_preds mismatch gracefully), skip cls_preds class mismatch. Reuse the YOLOX_CHECKPOINT_URLS dict by importing from yolox_lightning (import download_checkpoint and YOLOX_CHECKPOINT_URLS).

**forward** - Same as YOLOXLightningModel: RGB-to-BGR swap, export mode branching, training mode with targets, inference mode without.

**training_step** - Same as YOLOXLightningModel but also log dfl_loss if present in outputs.

**validation_step** - Inherit from YOLOXLightningModel pattern (compute predictions, convert targets, update metrics). Can delegate to base class or copy the YOLOX pattern.

**get_predictions** - Same as YOLOXLightningModel (output is already [B, N, 5+C] after DFL integral).

**configure_optimizers** - Same as YOLOXLightningModel (SGD with param groups, warmup + cosine).

**export_onnx** - Override to match YOLOX pattern: single output tensor "output" with dynamic axes {0: "batch_size"}, input name "input". The DFL integral is already in the forward graph so no special handling needed.

**on_train_epoch_start** - Same as YOLOX: unfreeze backbone at epoch N, enable L1 loss at epoch M.

Register two variants using @register decorator:
- `@register(name="DINOXMBaseline")` class DINOXMBaselineModel: defaults checkpoint_name="yolox_m.pth", use_dfl=False
- `@register(name="DINOXMDFL")` class DINOXMDFLModel: defaults checkpoint_name="yolox_m.pth", use_dfl=True

**models/__init__.py** - Add imports for DINOXLightningModel, DINOXMBaselineModel, DINOXMDFLModel. Add to __all__. This triggers Hydra registration when `import object_detection_training.models` runs in task_manager.py -- no changes to task_manager.py needed (task_manager.py line 28 already does `import object_detection_training.models  # noqa: F401` which auto-discovers all registered models via the __init__.py import chain).
