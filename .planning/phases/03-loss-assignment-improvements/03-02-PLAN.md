**test_dinox_mal.py** (TEST-03):

Create `_make_model` and `_make_targets` helpers following the pattern in test_dinox_soft_labels.py (duplicated per project convention -- no cross-test imports).

Tests for `matchability_score`:
1. `test_matchability_perfect_match`: When ious=1.0 and cls_scores=1.0, matchability=1.0
2. `test_matchability_zero_iou`: When ious=0.0, matchability=0.0 regardless of cls_scores
3. `test_matchability_formula`: Hand-computed example: ious=0.5, cls_scores=0.8, gamma=1.5 -> expected = 0.5^1.5 * 0.8^(-0.5) = 0.3536 * 1.1180 = ~0.3953. Verify with torch.allclose.
4. `test_matchability_batch`: Verify vectorized computation on multi-element tensors

Tests for `mal_weight`:
5. `test_mal_weight_at_one`: matchability=1.0 -> weight=1.0 (BCE equivalence, TEST-03 boundary)
6. `test_mal_weight_at_zero`: matchability=0.0 -> weight=2.0 (maximum amplification)
7. `test_mal_weight_monotonic`: For matchability values [0.0, 0.25, 0.5, 0.75, 1.0], weights are monotonically decreasing
8. `test_mal_weight_range`: All weights in [1.0, 2.0] for matchability in [0, 1]

Gradient tests:
9. `test_mal_gradient_flows_through_cls_scores`: Create cls_scores with requires_grad=True, ious with requires_grad=False. Compute matchability_score -> mal_weight -> backward. Assert cls_scores.grad is not None.
10. `test_mal_gradient_does_not_flow_through_ious`: Create ious with requires_grad=True. Compute matchability. Assert gradient does NOT flow (ious should be detached by the caller, but verify the function doesn't create unexpected gradient paths). Actually: the function itself doesn't detach -- the caller does. So this test should verify that if ious has grad, gradient does flow (function is transparent). The REAL test is integration: verify that in _get_losses, pred_ious_this_matching is detached. Add an integration test: create a DINOXHead with use_mal=True and use_soft_labels=True, run a forward pass with targets, verify loss.backward() succeeds without errors.

**test_dinox_tal.py**:

Create `_make_model` and `_make_targets` helpers (same pattern).

Tests for `TaskAlignedAssigner`:
1. `test_tal_output_tuple_length`: assign() returns a 5-tuple
2. `test_tal_output_shapes`: For a known input (e.g., 2 GTs, 100 anchors), verify:
   - gt_matched_classes shape [num_fg]
   - fg_mask shape [total_num_anchors], dtype bool
   - pred_ious_this_matching shape [num_fg]
   - matched_gt_inds shape [num_fg]
   - num_fg is int and equals fg_mask.sum()
3. `test_tal_topk_respects_limit`: With topk=3 and 2 GTs, num_fg <= 6 (at most topk per GT, minus conflicts)
4. `test_tal_conflict_resolution`: Create scenario where one anchor is top-k for two GTs. Verify it's assigned to the GT with higher alignment metric, not both.
5. `test_tal_no_candidates`: When no anchors pass spatial filtering (GT box outside image), returns num_fg=0 and empty tensors.
6. `test_tal_contract_matches_simota`: Create a DINOXHead with assigner_type="simota" and another with assigner_type="tal". Run both on the SAME input. Verify output tuple has same structure (same dtypes, same shape patterns relative to num_fg). Values will differ but shapes/types must match.
7. `test_tal_integration_forward`: Create DINOXHead with assigner_type="tal" and use_soft_labels=True. Run forward with targets. Verify loss is finite and backward succeeds.

For TAL tests that need realistic inputs, create synthetic data:
- Use 3 FPN levels with strides [8, 16, 32]
- Input size 640x640 -> anchor counts: 80*80 + 40*40 + 20*20 = 8800
- 2-3 GT boxes in reasonable positions
- Random cls/obj/bbox predictions
